# Maccy — форк с папками для закреплённых записей

> **English summary.** This is a personal fork of [Maccy](https://github.com/p0deje/Maccy)
> (based on tag `2.7.1`), built as `2.7.1-mod`. It adds folders and manual ordering for
> pinned items, removes the single-letter hotkey that pins used to carry (and with it the
> 21-pin limit), collapses a long history behind a "show more" row, and strips Sparkle so
> an official release can never overwrite an ad-hoc signed build. A prebuilt universal binary is
> published under Releases; it is ad-hoc signed, so it needs
> `xattr -dr com.apple.quarantine` after download. Building from source works too. Upstream is MIT licensed and so is
> this fork; all credit for Maccy goes to [Alex Rodionov](https://github.com/p0deje).

Форк сделан под один сценарий: когда закреплённых записей не десяток, а много,
и их нужно раскладывать по темам. Всё остальное — обычный Maccy 2.7.1.

## Чем отличается от оригинала

### 1. Папки для закреплённых записей

Закреплённые записи без папки ведут себя как раньше: они показываются вверху окна
или внизу — смотря что выбрано в **Настройки → Внешний вид → Прикрепить к**.
Строки папок идут следом; содержимое папки открывается **отдельной панелью сбоку** —
по наведению или клику. Панель сама выбирает сторону: справа, а если у правого
края экрана не помещается — слева.

Папки создаются, переименовываются, переставляются и удаляются в
**Настройки → Прикреплённые**. Удаление папки не удаляет записи — они
возвращаются в общий список.

### 2. Ручной порядок закреплённых

Порядок больше не зависит от времени копирования. В настройках список
иерархический: раздел «Без папки» и по разделу на каждую папку; внутри раздела
порядок меняется перетаскиванием или кнопками ↑/↓, а колонка «Папка» переносит
запись в другую папку.

### 3. Закрепление без горячей клавиши

В оригинале закрепление одновременно назначало записи букву-хоткей, и поэтому
закрепить можно было максимум 21 запись. В форке буква не назначается и не
показывается — **ограничение на количество закреплённых снято**.

### 4. Сворачивание длинной истории

Видимыми остаются первые N записей (по умолчанию 15), остальные прячутся за
строкой «Показать ещё N». Настраивается в **Настройки → Хранилище**. Поиск
всегда идёт по всей истории, а не по видимой части.

### 5. Автообновления вырезаны

Sparkle удалён из проекта целиком. Обновление = пересборка из исходников.
Причина в [Ограничениях](#ограничения-и-предупреждения).

## Установка

### Готовая сборка

Скачайте `Maccy-2.7.1-mod.zip` на странице
[Releases](https://github.com/faansfw/Maccy/releases/latest), распакуйте и
перенесите `Maccy.app` в «Программы». Дальше два обязательных шага:

```bash
# 1. Снять карантин. Сборка подписана ad-hoc, и без этого macOS откажется
#    её запускать со словами, что приложение повреждено.
xattr -dr com.apple.quarantine /Applications/Maccy.app

# 2. Запустить
open -a Maccy
```

После первого запуска выдайте доступ в **Системные настройки → Конфиденциальность
и безопасность → Универсальный доступ**, иначе вставка работать не будет.

Сборка универсальная — Apple Silicon и Intel, macOS 14 Sonoma или новее.
Контрольная сумма архива указана в описании релиза.

### Сборка из исходников

Нужен **Xcode 27 beta или новее** — командных средств разработки со Swift 5.8
не хватит. Зависимости подтянутся сами через Swift Package Manager.

```bash
git clone https://github.com/faansfw/Maccy.git
cd Maccy

export DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer
xcodebuild -project Maccy.xcodeproj -scheme Maccy -configuration Release \
  -derivedDataPath ./DerivedData \
  -destination 'generic/platform=macOS' \
  CODE_SIGN_IDENTITY="-" CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM="" \
  PROVISIONING_PROFILE_SPECIFIER="" build
```

Клонируется сразу ветка `mod` — она в репозитории основная. `generic/platform=macOS`
собирает универсальный бинарник; для сборки только под свою машину можно
указать `-destination 'platform=macOS,arch=arm64'`, это заметно быстрее.

Установка собранного (сначала сохраните копию текущего приложения, если оно уже
стоит):

```bash
pkill -x Maccy
rm -rf /Applications/Maccy.app
ditto ./DerivedData/Build/Products/Release/Maccy.app /Applications/Maccy.app
open -a Maccy
```

Своей сборке карантин снимать не нужно — он появляется только у скачанного файла.

## Ограничения и предупреждения

- **Подпись ad-hoc, без нотаризации.** Во-первых, скачанному архиву нужно снимать
  карантин вручную. Во-вторых, macOS считает такую сборку другим приложением,
  поэтому доступ в «Универсальный доступ» приходится выдавать заново после каждой
  замены приложения. Подписать как положено можно только с платным Apple Developer
  ID — его нет, поэтому доверять сборке приходится на слово.
- **Не ставьте Maccy поверх из Homebrew или с сайта** — официальная сборка затрёт
  форк. Ровно поэтому из проекта вырезан Sparkle.
- **История сохраняется.** Новые поля добавляются к существующей модели данных,
  миграция проходит автоматически. Но откат на официальную сборку после
  использования форка не тестировался — сделайте копию
  `~/Library/Containers/org.p0deje.Maccy`, прежде чем экспериментировать.
- Тесты `ClipboardTests.testIgnoreApplication` и `testIgnoreAllApplicationsExcept`
  падают — они падают и на чистом апстриме 2.7.1, потому что зависят от того,
  какое приложение активно во время прогона. Это не регрессия форка.

## Как это устроено

Заметки для тех, кто будет дорабатывать форк.

- **Закреплённые и папки — одна сущность.** Папка хранится прямо на записи
  (`HistoryItem.folderName`), список папок — в `Defaults[.pinFolders]`.
  Отдельной модели «сниппетов» намеренно нет: это дублировало бы стоковый
  механизм закрепления.
- **Панель папки не может быть key-окном.** `FloatingPanel.resignKey()` закрывает
  попап при потере фокуса, поэтому обычный SwiftUI `.popover` (он создаёт своё
  окно) здесь не работает — содержимое папки рисует `FolderFlyoutPanel`.
- **Вставка закреплённой записи возвращает её в историю как «новую»**, поэтому
  `History.add` переносит на неё не только `pin`, но и `folderName`/`order` —
  иначе запись выпадала бы из папки.
- Коммиты в ветке `mod` разбиты по функциям, чтобы их было видно по отдельности;
  собирается и проверялось итоговое состояние ветки, промежуточные коммиты —
  логическая разбивка одной правки.

## Подтягивание изменений из апстрима

```bash
git remote add upstream https://github.com/p0deje/Maccy.git
git fetch upstream --tags
git checkout mod
git rebase <новый-тег>      # например 2.8.0
```

Конфликты ожидаемы в `PinsSettingsPane.swift`, `PinsView.swift`,
`History.swift` и `Sorter.swift` — именно эти файлы форк переписывает сильнее
всего.
